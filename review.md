# Review — rate limit, Фазы 1–4

Отчёт по изменениям: подключение rate limit + Фаза 1 (детекция ПД и аудит) +
Фаза 2 (мультисистемность и контроль доступа) + Фаза 3 (метрики) + Фаза 4
(тесты, производительность, упаковка). Контракт `POST /process` и
идемпотентность по `payload_id` не затронуты.

## Исправленные баги

### 1. `\b` не работает с кириллицей → ФИО не детектировалось вообще

**Файл:** [internal/service/service.go](internal/service/service.go)

В Go используется движок RE2, где `\b` — это **ASCII**-граница слова. Регэксп
ФИО `\b([А-ЯЁ][а-яё]+)...` никогда не срабатывал: между пробелом и кириллической
буквой ASCII-границы нет. Баг присутствовал и в исходном коде — ни одно
кириллическое ФИО не маскировалось.

*Исправление:* убран `\b` вокруг кириллических подвыражений в `reFIO`,
`reFIOInitialsL`, `reFIOInitialsR`. `\b` вокруг цифр (паспорт, карта, даты, коды)
оставлен — там он корректен, т.к. цифры являются ASCII word-символами.

### 2. Жадный regexp карт мог захватывать неполный номер

**Файл:** [internal/service/service.go](internal/service/service.go)

Прежний `\b(?:\d[ -]*?){13,19}\b` с ленивым квантификатором мог захватывать
меньше 16 цифр, из-за чего проверка Луна падала на валидных картах.

*Исправление:* заменён на `\b\d(?:[ -]?\d){12,18}\b`. Проверено: валидный по Луну
номер (`4539 1488 0343 6467`) ловится, невалидный (`4276 3800 1234 5678`) —
корректно отсекается.

### 3. `RateLimitMiddleware` был написан, но не подключён

**Файл:** [internal/transport/http/handler.go](internal/transport/http/handler.go)

Middleware существовал, но в `SetupRouter` регистрировался только
`RecoveryMiddleware`. Под перегрузкой сервис отдавал таймауты вместо `429`, что
по регламенту AlfaSonar считается неответом и приближает останов прогона по
5 невалидным ответам подряд (circuit breaker).

*Исправление:* добавлен `r.Use(RateLimitMiddleware())` — теперь при превышении
порога возвращается `429` с заголовком `Retry-After: 1`.

### 4. O(n²) в маскировании → таймаут на больших текстах *(найдено в Фазе 4)*

**Файл:** [internal/service/service.go](internal/service/service.go)

Перевод байтового офсета матча в рунную позицию делался как
`len([]rune(input[:sIdx]))` — на каждый матч заново от начала строки. На тексте
~160k токенов это давало **11.2 с** на один вызов `Mask` (бенчмарк) — за
пределами и ориентира 1 с, и таймаута AlfaSonar 10 с.

*Исправление:* индекс «байт → руна» строится за один проход (`buildRuneIndex`),
конвертация офсета стала O(1). Результат бенчмарка: **11.2 с → 1.36 с** на
~160k токенов (≈0.85 с на 100k). Функциональность не изменилась (тесты зелёные).

### 5. Ложные срабатывания ФИО на ролевых словах и топонимах

**Файл:** [internal/service/service.go](internal/service/service.go)

Регэксп `[А-ЯЁ][а-яё]+ [А-ЯЁ][а-яё]+` матчил любые два слова с заглавной буквы:
«Москва Сити», «ООО Ромашка», а также захватывал ведущее общеупотребимое слово
(«Клиент Иванов» — маскировался и «Клиент»).

*Исправление:*
- stop-list топонимов/юрлиц (`stopTokens`) — совпадение отбрасывает матч целиком;
- список публичных личностей (`famousNames`) — «Александр Пушкин» не маскируется;
- срезка ведущих ролевых слов (`roleWords`) — «Клиент»/«Поэт» сохраняются, а имя
  за ними маскируется.

## Что добавлено в Фазе 1

### Новые типы ПД (детекторы)

| Тип | Что ловит |
|---|---|
| `ADDRESS` | индекс, страна, город (`г.`), улица (`ул.`/проспект/переулок/…), дом (`д.`), квартира (`кв.`) |
| `PASSPORT` (расширенно) | форма с разделителями «серия 4509 номер 123456», `№ 123456` |
| `PASS_AUTHORITY` | орган выдачи: ОВД, УФМС, ОУФМС, ГУ МВД, УМВД, ГУВД, «отделом…» |
| `BIRTHPLACE` | место рождения по маркерам «место рождения…», «родился в…» |
| `CITIZENSHIP` | «гражданство …», «гражданин РФ/России» |
| `CARD_HOLDER` | имя держателя карты латиницей (`IVAN PETROV`) |
| `DATE` (расширенно) | любой числовой порядок + текстовые даты («12 мая 1995 года») |

### Улучшения существующей детекции

- ФИО: капитализированное (до 4 слов, чтобы поглотить роль + Ф/И/О) и форма
  инициалов (`Иванов И.И.`, `И.И. Иванов`).
- Регистронезависимость (`(?i)`) во всех контекстных правилах.
- ФИО после сильных маркеров («на имя …», «ФИО: …») — регистронезависимо.

### Аудит без утечки ПД

- Метод `Process` собирает список уникальных найденных типов и пишет
  структурный лог через `log/slog`: `payload_id`, этап, список типов, счётчик.
- **Исходные значения ПД в лог не попадают** — только типы и их количество.

### Архитектура

- Детекторы вынесены в срез `s.detectors` (`regexp` + номера групп захвата).
  Новый тип ПД добавляется одной строкой без правки ядра маскирования — прямое
  требование ТЗ о расширяемости.
- Ядро маскирования (руны, слияние спанов, сохранение форматирующих символов,
  «банковский» стиль краёв) не изменено.

## Что добавлено в Фазе 2 (мультисистемность и контроль доступа)

**Файлы:** [internal/config/config.go](internal/config/config.go),
[internal/service/service.go](internal/service/service.go),
[internal/transport/http/handler.go](internal/transport/http/handler.go),
[config/systems.json](config/systems.json), [config/README.md](config/README.md).

- **Белый список систем-потребителей.** Система определяется заголовком
  `X-System-ID`. Незарегистрированная или отключённая (`enabled: false`) система
  получает `403`.
- **Правила в разрезе системы.** Для каждой системы настраивается список типов
  ПД для маскирования (`mask_types`, пустой = все) и флаг демаскирования
  (`demask_enabled`). При `demask_enabled: false` обратный шаг возвращает
  присланную строку без раскрытия оригинала.
- **Безопасный дефолт.** `auth_enabled: false` по умолчанию — контроль доступа
  выключен, маскируются все типы. Так проверяющая система AlfaSonar не
  отклоняется из-за отсутствия `X-System-ID`. Включение — флагом в
  `config/systems.json` или `AUTH_ENABLED=true`.
- **Конфиг-файл опционален.** Отсутствие/ошибка чтения `config/systems.json`
  (путь переопределяется `CONFIG_PATH`) → безопасный дефолт, сервис стартует.
- **Инструкция по настройке** — [config/README.md](config/README.md), ровно
  5 предложений (требование ТЗ).

## Что добавлено в Фазе 3 (метрики)

**Файлы:** [internal/metrics/metrics.go](internal/metrics/metrics.go),
[internal/transport/http/middleware.go](internal/transport/http/middleware.go),
[internal/transport/http/handler.go](internal/transport/http/handler.go),
[cmd/main.go](cmd/main.go).

- **Пакет `metrics`** — потокобезопасный сборщик на атомарных счётчиках
  (без блокировок, рассчитан на 1000+ RPS): число запросов, сумма latency,
  токены, `5xx`, `429`, in-flight.
- **`MetricsMiddleware`** — замеряет задержку, статус и объём каждого запроса.
  Токены оцениваются как `payload_bytes / 4` (по README); **содержимое payload
  не читается и не логируется**.
- **`GET /metrics`** в формате Prometheus text exposition: `pd_requests_total`,
  `pd_tokens_total`, `pd_errors_5xx_total`, `pd_rate_limited_total`,
  `pd_inflight_requests`, `pd_avg_rps`, `pd_avg_tps`, `pd_avg_latency_seconds`
  и гистограмма `pd_request_latency_seconds` (бакеты сгущены вокруг 1 с).
- **Порядок middleware:** `/metrics` зарегистрирован до metrics/ratelimit —
  не искажает собственные метрики и **отвечает даже под перегрузкой** (не попадает
  под `429`). Без внешних зависимостей — `go.mod` не раздувается.

## Дополнительно: вариативность написания ФИО (морфологический детектор)

**Файл:** [internal/service/service.go](internal/service/service.go)
(`findFIOMorph`, `classifyName`, `expandInflections`).

Капитализированный детектор не покрывал строчное написание и имена без
слова-маркера. Добавлен морфологический детектор, независимый от регистра и
маркеров:

- **Классификация слов по окончаниям:** фамилии (`-ов/-ова/-ев/-ин/-ская/-ян/
  -идзе/-швили/-ко/…`), отчества (`-ович/-евич/-овна/-евна/-ична`), словарь
  распространённых имён.
- **Падежные формы** имён генерируются (`expandInflections`): ловятся «для
  сергея», «ивану», «анне», а не только именительный падеж.
- **Правило против ложных срабатываний:** одиночное слабое окончание (`-ин`
  как в «бензин», `-ко` как в «молоко») **никогда не срабатывает само**.
  Окно из 2–3 слов маскируется, только если все слова именоподобны И есть
  сильный якорь (словарное имя или отчество). Одиночное — только отчество.
- **Мостик «фамилия — [неизвестное имя] — отчество»** ловит «Гагарян Ашот
  Арутюнович» целиком, даже если имя не в словаре.
- **Списки-исключения:** нарицательные (бензин, магазин, молоко…), служебные
  слова, топонимы/юрлица и публичные личности не маскируются.

Проверено: `иванов иван`, `пётр воробьёв`, `для сергея петрова`,
`гагарян ашот арутюнович` — маскируются; `бензин`, `молоко`, `магазин`,
`Александр Пушкин`, `Москва Сити` — нет.

## Ограничения / TODO

- `RE2 без lookahead/lookbehind` — контекстные правила построены на группах захвата.
- Морфологический ФИО-детектор не ловит: одиночную фамилию без имени/отчества
  рядом (напр. «Саакашвили пришёл») и одиночное имя («позвони Анне») — намеренно,
  чтобы не плодить ложные срабатывания. Словари имён/нарицательных расширяемы.
- Производительность: ~0.85 с на 100k токенов (худший случай) — в пределах
  таймаута, но близко к ориентиру 1 с. Дальнейшее ускорение возможно за счёт
  объединения regexp-проходов или однопроходного сканера — при необходимости.
- Все 4 фазы плана README выполнены. Из общего списка задач (AGENNT.md) остаются
  необязательные бонусы раздела 6 ТЗ: токенизация/синтетика, RPS 2000,
  общий кэш для горизонтального масштабирования, условное (составное) маскирование,
  прочие удостоверения личности.
- Healthcheck-эндпоинт и docker-compose (гигиена деплоя) — по желанию.
