# Горизонтальное масштабирование и нагрузка (RPS 2000)

## Проблема
In-memory кэш живёт в одном процессе. При нескольких инстансах за балансировщиком
демаскирующий запрос (шаг 2) может попасть на другой инстанс, где пары
`payload_id → оригинал` нет. Это блокирует горизонтальное масштабирование.

## Решение
Кэш вынесен за интерфейс `service.Store` (`Get`/`Set`). Реализации:
- **`ShardedCache`** — in-memory, 64 шарда (по умолчанию, для одиночного инстанса).
- **`RedisStore`** — общее хранилище: любой инстанс видит одни и те же пары,
  TTL и вытеснение выполняет Redis.

Выбор бэкенда — переменными окружения:
```
CACHE_BACKEND=redis
REDIS_ADDR=redis:6379
```
По умолчанию `memory`. При `redis` и недоступности Redis — безопасный фолбэк на
in-memory (сервис всё равно стартует).

## Схема развёртывания
`docker-compose.yml` поднимает: **Redis** + **3 инстанса бэкенда** (`CACHE_BACKEND=redis`)
+ **nginx** (round-robin) на порту `8080`.

```
клиент → nginx :8080 → app1 / app2 / app3 → Redis (общее состояние)
```
Маска может выполниться на app1, а демаска — на app3: состояние общее, результат
корректен.

## Запуск
```bash
docker compose up --build -d
# точка входа — балансировщик:
curl -X POST http://localhost:8080/process \
  -H "Content-Type: application/json" \
  -d '{"payload":"Иванов Иван, паспорт 4509 123456","payload_id":"demo"}'
```
Масштабирование числа инстансов — правкой `docker-compose.yml` (сервисы `appN`
и `upstream` в `deploy/nginx.conf`).

## Нагрузочный тест
Встроенный генератор (пары маска+демаска, уникальные `payload_id`, проверка
round-trip):
```bash
cd backend
go run ./cmd/loadtest -url http://localhost:8080/process -c 300 -d 60s
```
Выводит RPS (HTTP-запросов/с), среднюю latency и число несовпадений демаскирования
(должно быть 0 — доказывает, что общее состояние работает между инстансами).

Метрики также доступны на `http://localhost:8080/metrics` (Prometheus):
`pd_avg_rps`, `pd_avg_latency_seconds`, гистограмма `pd_request_latency_seconds`.

## Замечания по производительности
- `/metrics` и rate-limit не мешают друг другу; `/metrics` отвечает даже под
  перегрузкой.
- Маскирование — O(n) по длине текста; на типовых запросах latency — доли мс.
- Для целевых 2000 RPS масштабируется числом инстансов бэкенда за nginx; Redis —
  единая точка состояния (при необходимости — Redis Cluster/Sentinel).
