# Настройка систем-потребителей

Контроль доступа включается флагом `auth_enabled: true` в `config/systems.json` (или переменной окружения `AUTH_ENABLED=true`), и по умолчанию он выключен — тогда обрабатываются все запросы с маскированием всех типов. Чтобы добавить систему, впишите её идентификатор в объект `systems` и передавайте его в заголовке `X-System-ID`; незарегистрированная или отключённая (`enabled: false`) система получает `403`. Список типов ПД для маскирования задаётся в `mask_types` (пустой список = маскировать все типы; допустимые значения: `FIO`, `PHONE`, `EMAIL`, `PASSPORT`, `PASS_CODE`, `PASS_AUTHORITY`, `DATE`, `DRIVER`, `INN`, `CARD`, `CARD_EXP`, `CVV`, `PIN`, `CARD_HOLDER`, `ADDRESS`, `BIRTHPLACE`, `CITIZENSHIP`, `PASSPORT_INTL`, `SNILS`). Стратегия маскирования системы задаётся полем `strategy`: `token` (плейсхолдеры `[FIO_1]`, по умолчанию) или `asterisks` (звёздочки). Демаскирование включается/выключается флагом `demask_enabled` (при `false` обратный шаг возвращает присланную строку), а поле `strategy` задаёт вид маски: `token` (плейсхолдеры `[FIO_1]`, по умолчанию), `asterisks` (звёздочки) или `synthetic` (правдоподобные фейки). Глобальный флаг `composite_masking: true` (по умолчанию `false`, либо `COMPOSITE_MASKING=true`) включает составное маскирование — `PIN`/`CVV`/`CARD_EXP` маскируются только если в тексте присутствует карта; путь к файлу настроек переопределяется переменной `CONFIG_PATH`.
